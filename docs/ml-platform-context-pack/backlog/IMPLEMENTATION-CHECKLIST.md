- [~] **2.1** *(BUILD-AS, ADR-P2-04)* Campaign workflow; DEFINE refuses to start without `delta_practical` *(§10, §8)* — **DEFINE and the phase machine are done; two of the three terminal rules are not.** The campaign's state is a fold over `mlops.campaign_event` and there is no status column: `ledger::phase` holds the thirteen §10 phases, the legal transitions, and `fold`, which refuses a log that does not open with `define`, an illegal transition, or anything appended after an ending. Migration 0052 adds `seq` (the database assigns the position, not the writer), a unique `(campaign_id, seq)`, and a BEFORE INSERT trigger enforcing the same transition table against every writer. `DEFINE` now opens the log in the same transaction that writes the campaign row. `JobKind::Campaign` and `api::campaign_driver::CampaignWorker` drive it: each phase's work is a child job at `(campaign job, seq)`, created through `JobStore::submit_child_once` — created first, recorded second, so a driver killed in between re-derives the same position and reuses the child rather than starting a second one (AT-59, `pg_campaign`). **Not done:** `DIMINISHING_RETURNS` and `CONVERGED` need the confidence sequence from 2.12 and are reported by the driver as `NotComputable` rather than approximated; `BUDGET_EXHAUSTED` is live. The child worker kinds for `Study`, `GateAdvance`, `EvalTask` and `ResearchRun` are not registered yet, so a campaign run today fails at its first dispatching phase with `no_worker` — visibly, as a failed child job, leaving the log where it is.
- [x] **2.2** Job state machine incl. `DEDUPLICATED` via config-hash *(§9)* — the mapping is typed and there is no substring matching left on any settlement path (ADR-P2-30). `JobError` carries a REQUIRED `ledger::TerminalReason` with no serde default; `RunStatus::Failed(TerminalReason)` makes a Run that failed without saying how unrepresentable; the backtest driver's `PhaseFailure` and the model-registry job state each carry one, chosen where the failure happens. The trainer sidecar classifies its own exceptions by **type** (`app/failures.py`) and returns `terminal` on the wire; `train_torch_model` raises `NanDivergence` on a non-finite loss, which is what makes `nan_divergence` an observation rather than a label. Migration 0051 backfills historic `jobs.error` rows and a CHECK refuses new ones without the field. `asha_stopped` settles `right_asha` (AT-60, `ledger::state` and `jobs::types` tests). The four sniffers that used to default everything unrecognised to `dependency_failure` are deleted.
- [x] **2.3** Ray execution plane; Kueue admission with mandatory `max_gpu_hours`, no default *(§8, ADR-P2-05)* — **N/A as systems**; the requirement that survives is built. `require_gpu_budget` refuses any `Trainer`-class submission (`Train`, `Hpo`, `PredictSeries`) whose manifest has no positive finite `max_gpu_hours`, with a `422 max_gpu_hours_required`; the rule follows the *worker class*, not a hand-maintained list, so a new trainer kind inherits it. The worker enforces the same number at the other end with a hard timeout that settles `budget_exceeded` → `right_budget` censoring. There is no platform default anywhere on the path (AT-66). Quota and fairness remain the job service's caps and queues.
- [~] **2.4** Bit-reproducible checkpointing: RNG, optimizer, dataloader position, AMP scaler *(§9, ADR-P2-07)* — **the contract is enforced; the per-framework reproducibility measurement is not yet run.** `jobs::checkpoint::CheckpointManifest` is sealed — `parse` is the only constructor — and the artifact registry calls it before storing any `checkpoint` artifact, so a partial checkpoint cannot exist. Every contract field is refused **by name**: the four RNG sources (an empty `torch_cuda` is a valid answer for a CPU run, an absent one is not), the optimizer and scheduler refs, the dataloader position, the AMP scaler state, and the `code_hash`/`image_digest`/`dataset_id` triple that says which computation this checkpoint belongs to. A GBDT checkpoint must declare the determinism flags that were actually in effect — LightGBM without `force_row_wise` builds histograms in thread-scheduling order and differs run to run on one machine. The cadence is Young–Daly `√(2·cost·MTBF)`, and an **unmeasured** cost returns no interval rather than a made-up one. `apps/model-trainer/app/checkpoint.py` is the producing half; its `BIT_IDENTICAL_FRAMEWORKS` set is deliberately **empty**, so every framework currently declares `resume_support: unsupported`. **Not done:** AT-61's eval task — train `n`, resume at `n−2`, assert bit-identical — which is what would let a name be added to that set.
- [x] **2.5** Preempt → recover → resume without a new `trial_id` *(§9, §17, ADR-P2-07)* — `jobs::checkpoint::plan_resume` has exactly three outcomes and **none of them mints a trial**: `Resume` from a checkpoint that matches this computation and claims bit-identical resume; `Restart` from step 0 under the same trial (no checkpoint, a checkpoint from different code/image/dataset, or a framework whose resume is not bit-identical) carrying *why*; and `Abandon` — `checkpoint_invalid`, settling `preempted_abandoned` — for a stored checkpoint that fails the contract. That last case is deliberately not a restart: something wrote it, the registry should have refused it, and treating it as merely absent would hide that. Freeze-thaw is off until `freeze_thaw_worthwhile` sees a **measured** resume cost under 15 % of a rung (§11.3); an unmeasured cost is not cheap.
- [x] **2.6** Searcher auto-selection from (B, D, P) *(§11.1, ADR-P2-08)* — `research::search::select_searcher` is §11.1's table as a pure function of facts the campaign already declared, returning an `Answer<SearchPlan>` at `decision_tier = rule` with the rationale attached, so "which optimiser did you use and why" is answerable from the ledger instead of from whoever edited the config last. Arms: portfolio replay below 10 trials (a ten-sample optimiser is a random draw with extra steps), prior-weighted random below 30 (a model fitted on that many points is fitting noise), TPE for mixed/conditional spaces, GP-BO for **model** hyper-parameters only. GP-BO over strategy parameters is deferred and the rationale *says so* rather than the arm silently not appearing; a budget past 200 sets `beyond_supported_budget`, which makes ADR-P2-08's CMA-ES revisit trigger visible rather than remembered. ASHA joins at parallelism ≥ 8.
- [x] **2.7** √D-scaled LogNormal lengthscale prior for GP-BO *(§11.1)* — `apps/model-trainer/app/gp_prior.py`: `ℓ ~ LogNormal(μ₀ + log(D)/2, σ₀)`, so the prior's **median lengthscale is √D** on the unit cube. The reason is geometric: typical pairwise distance in D normalised dimensions grows like √D, and a GP whose prior does not know that puts nearly all its mass on lengthscales shorter than any real distance, concludes every observation is independent of every other, and returns the prior mean everywhere — an expensive random search. Trust regions and learned embeddings are deliberately not here; both are second moves.
- [x] **2.8** ASHA hardening — all five mitigations *(§11.2, ADR-P2-09)* — `research::search::AshaLadder`, defaults with **no per-mitigation off switch**, because a switch is a thing somebody turns off at 2 a.m. to make a sweep finish. (1) A rung is scored on the sealed distribution's worst-case-robust statistic or the last-three mean, never a single last value. (2) `grace_rungs` protects an unfinished rung; cold start is one full rung. (3) PASHA soft ranking keeps everyone within ε of the cut — a candidate indistinguishable from a survivor has not been shown to be worse — with ε = 0 at cold start, recorded as the rule tier rather than as a number nobody measured. (4) `wilcoxon_applicable` refuses to run below three replicates, where the signed-rank test cannot reject at any conventional level and its p-value reads as evidence of no difference. (5) `needs_reseed` returns the top three for re-running on fresh **platform-held** seeds before an incumbent is crowned — three runs against ASHA's whole failure mode, which is promoting the configuration that got lucky early.
- [x] **2.9** ≥5% exploration floor, not writable, not in any tool schema *(§4.5, INV-21)* — three mechanisms: `ExplorationFloor` has no constructor that accepts a value below 5%; `mlops.campaign` CHECKs it independently of the Rust type (live test writes the row directly and is refused); and `Dispatcher::draw` — the only thing that turns a candidate set into a choice — takes **no floor argument** and decides exploration itself from the campaign's floor and the achieved fraction. `below_floor()` is the alarm condition. The tool-schema half was already closed (AT-24).
- [x] **2.10** M3-backed learning-curve stopping rule *(§11.3, ADR-P2-10)* — `research::search::EarlyStopper` answers from the median stopping rule today and from `P(final > incumbent + δ | partial) < 0.05` when a curve posterior exists, **through the same interface**, which is what makes the eventual rule-versus-learned A/B a query rather than a rewrite. A stop carries `Censoring::RightAsha` and there is no path that makes it `Failed`: a stopped trial is a censored observation, and counting it as a failure is how a search that works starts looking like one that does not. No peers to compare against is not a reason to stop — continuing costs compute, stopping costs the answer, and only one of those is recoverable.
- [x] **2.11** Post-hoc pipeline in fixed order; threshold closed-form, never tuned *(§11.4, ADR-P2-11)* — `apps/model-trainer/app/posthoc.py` is one function, four steps, one order: soup → Caruana greedy ensemble **with replacement** over stored per-fold OOS predictions → calibrate on the dedicated `cal` role → closed-form threshold. `run_posthoc` has no ordering parameter, and neither does `PostHocRequest` on either side of the wire; a step that does not apply is returned as `skipped` (a GBDT report still has four steps, the first saying `not_applicable`) so the sequence is auditable from the artifact. Calibrators are Platt-on-logits, beta and quadratic — all monotone, tested to be; binning calibrators are refused by name with the reason. **AT-35 is live** twice: `at35_the_decision_threshold_performs_no_search` asserts `decision_threshold(costs: CostMatrix)` is its whole signature and that its body contains no loop, grid or argmax, and `dispatch_posthoc` refuses a response whose steps came back in a different order. 13 Python tests, run in CI.
- [x] **2.12** Comparison protocol: ~29 paired replicates, P(A>B) rule, Holm/BH, anytime-valid CIs *(§11.5, ADR-P2-12)* — `backtest::stats::compare`. `Comparison` is sealed: private fields, no public constructor, and a static test (`only_the_protocol_constructs_a_comparison`) keeps `ComparisonPlan::judge` the only way to mint one, so a verdict cannot arrive without its profile, `N_eff`, `delta_practical`, both trial counts and its flags. Replicates are the enumerated product of window × cost perturbation (±20 %) × fill seed, generated from the pair's identity and applied identically to both sides; a mismatched or unpaired replicate is refused rather than zipped. `confidence_sequence` is the predictable plug-in empirical-Bernstein CS (Waudby-Smith & Ramdas), anytime-valid so sampling until separation is legitimate; differences are mapped through a **declared** `RopeScale` and an observation outside it is an error, never a clipped value. `holm_adjusted` for promotion, `bh_adjusted` for screening, with a test that Holm is uniformly the stricter of the two. **Not consumed yet:** nothing calls `judge` — the COMPARE phase's worker is 2.1's gap — so the `StudyResult`-cannot-substitute property is a design consequence, not yet an enforced one.
- [x] **2.13** Multiple Comparison Matrix; critical-difference diagrams banned *(§11.5, ADR-P2-13)* — `ComparisonMatrix` stores both directions of every pair with the mean difference, win/tie/loss and a Wilcoxon signed-rank p-value that is documented and named as descriptive only. **AT-62 is live**: `at62_no_critical_difference_renderer_exists` scans every `.rs`/`.ts`/`.tsx`/`.js`/`.jsx`/`.py`/`.sql`/`.json` file in `crates`, `apps`, `frontend`, `web` and `ui` for `critical_difference` / `cd_diagram` / `nemenyi` and fails the build on a hit.

## Phase 4 — Internal models, in ROI order

> **Decided (ADR-P4-01):** build 4.1 and every model's *rule tier* now; each *learned tier* is behind an explicit ledger-size trigger (plan §Phase 4 table). The checkboxes below are ticked when the rule tier ships with `decision_tier` logging; the learned tier is a separate, later tick.

- [x] **4.1** Cold-start ladder `analytic/rule → shrunk → learned` with `decision_tier` logged *(§13.1, ADR-P4-01)* — `ledger::internal` holds the framework. `Answer<T>` carries its `Rung` **and** the `LadderEvidence` it was chosen on, inseparably: a number whose provenance is optional is a number that gets reported without it, and the eventual rule-versus-learned comparison is then a query rather than an excavation. `Rung::Analytic` records as `decision_tier = rule` — the ledger's question is "did a fitted model decide this", and for both the answer is no. `TRIGGERS` states every learned tier's ledger-size threshold from the reference, per model, each naming what its groups count (M5's are *passes*, not gated candidates). A **met trigger is not a trained model**: `choose_rung` takes `learned_available` separately, so a platform with the data but no fit still answers `rule` rather than claiming a tier it does not have.
- [x] **4.2** M1 cost predictor *(Tier A)* — `jobs::models::estimate_cost`: `rows × features × steps / throughput`, reported as a **band** (×3 either way) rather than a point, because this formula counts multiply-accumulates and nothing else — a run that waits on its dataloader takes twice what it says, and a narrow band would be a claim about I/O the model does not make. An unknown hardware class yields an infinite estimate rather than a default. Learned tier at ≥ 200 runs per (flow family, hw class); the trigger is stated and checked, and a met trigger still answers `analytic` until something is actually fitted.
- [x] **4.3** M2 failure classifier *(Tier A)* — `jobs::models::predict_failure`: does the working set fit in 80 % of the device (the remainder is fragmentation and the activation peak no parameter count predicts), and is the learning rate inside the envelope its optimiser survives (adaptive tolerates ~2 orders of magnitude more than plain SGD). Its third answer is `NothingPredictable`, which is **not** "it will work": most failures are only discovered by running, and the pre-flight claims nothing about them. The predictions name the `TerminalReason` they expect, so a prediction and an outcome are comparable without a mapping.
- [~] **4.4** M3 learning-curve extrapolator *(Tier A)* — the rule tier is `research::search::EarlyStopper::median_rule` (2.10) and the learned tier's interface is already there: `with_posterior` answers through the same signature, so the eventual A/B is a query. Learned tier deferred behind ≥ 1 000 curves with ≥ 20 % complete (ADR-P4-01).
- [~] **4.5** M5 gate pre-screener *(Tier B)* — `ledger::tiers::prescreen`, monotone in the Gate 2/3 margin with `calibrate_prescreen` setting the 99 %-recall operating point. The asymmetry is the design: a screened-out passer is a discovery nobody knows was lost, a doomed candidate costs one gate run. Uncalibrated it screens nothing; below 30 observed passers there is no operating point. Its trigger counts **passes**, not gated candidates. Learned tier deferred.
- [~] **4.6** M9 proposal ranker *(Tier B)* — `ledger::tiers::rank_proposals`, `mean + κ·σ` with κ = 2 (not tuned: tuning κ against observed outcomes fits the acquisition to the answers it was meant to find). Without a surrogate it returns **no ranking** rather than ranking on the mean, because a mean ranking is pure exploitation wearing the acquisition's name. Learned tier deferred.
- [~] **4.7** M4 config surrogate *(Tier B)* — the rule tier is the searcher's own model, selected by `research::search::select_searcher` (2.6). Learned tier deferred behind ≥ 1 500 runs across ≥ 30 tasks.
- [~] **4.8** M8 strategy-family recommender — **per-tenant always** *(Tier B, §7.4)* — `ledger::tiers::recommend_families` ranks on the **Wilson lower bound** of the pass rate, not the raw rate, because the raw rate puts one-for-one above nineteen-for-twenty and that ordering is an artefact of the sample size. Per-tenant is the model's scope, not a convenience: pooled win rates would tell each tenant which families work for the others. Learned tier deferred.
- [x] **4.9** M11 metric-stream anomaly detector *(Tier A)* — `jobs::models::detect_anomaly`: hard rules first (a non-finite loss is terminal, not an outlier to be scored; a loss that has not moved is flat), then a **local** robust-z and a one-sided CUSUM. Local because a healthy curve decelerates — scoring its increments against one spread calls the whole first half anomalous — and because a single wild value inflates the global spread enough to mask itself, which is exactly the case the detector is for. CUSUM is centred on **zero**, not the observed mean increment, since centring on the mean subtracts out the drift being looked for. Only points with a full window on both sides are judged.
- [~] **4.10** M13 step critic PRM *(Tier B)* — `ledger::tiers::critique_step`: hard rules first (a repeated step is a loop, a step that moved nothing is the model talking to itself — both certain, neither borderline), then judge triage. Learned PRM deferred behind 3 000 labelled steps.
- [x] **4.11** Learning-debt retraining trigger *(§14.1, R-11)* — `ledger::tiers::learning_debt`: retrain iff `ρ > c_churn/(c_churn + c_wait)`. A calendar cannot know whether a model has drifted and a dashboard nobody looks at knows less; the threshold is the ratio of the two costs that actually trade off. Unmeasured costs produce **no** trigger rather than a default one.
- [x] **4.12** Tier A/B/C promotion machinery; frozen ledger holdout; auto-rollback *(§14.3)* — `ledger::tiers::authorise_promotion` mints a sealed `PromotionCase` and refuses, by name, on four conditions: the platform frozen (4.16), the challenger not evaluated on the **frozen seed holdout** (a win on anything else is a win on data the champion also shaped), no win under §11.5's protocol, and — for Tier B — a breached entropy floor (promoting on a collapsed policy compounds the collapse: the new champion was chosen from the narrow slate the old one produced) or no named approver. Only Tier A auto-rolls-back; an automatic rollback of a Tier-B model is an automatic reversal of a human decision. Tier C does not exist in the registry at all (`no_tier_c_models` CHECK).
- [x] **4.13** Collapse guards: accumulate-only sets, real-outcome requirement, KL + Wasserstein *(§13.4)* — **the two structural guards are types; the distance tests are not built.** `TrainingRange` has no `from` field: a set is `[0, seq_max]` and "start later" is not expressible, because a sliding window is how a model ends up trained only on what the current policy recently chose to try. `TrainingSet::build` is the only constructor and refuses a set with no `paper`/`live` outcome (a model trained purely on backtests has learned what the simulator does), any overlap with the frozen seed holdout, or any set at all while `internal_model_freeze` is on. **Not done:** the KL and Wasserstein distances against the seed holdout.

- [x] **5.1** NATS JetStream → SSE; viewer-scaled connections *(§16.1)* — the SSE path existed; the trainer-side bound is now built. `apps/model-trainer/app/telemetry.py` is a **drop-oldest** bounded queue: an unbounded one turns a slow consumer into an OOM kill of the training run, and a blocking send turns it into a GPU stalling on a socket. Oldest rather than newest, because dropping the newest keeps a stale view that never catches up and *looks live*. The drop count travels with every batch and is never reset on read — a gap the consumer cannot see is a gap it reads as quiet, and a chronically-behind consumer would otherwise hide itself (AT-55).

The panel sits above the model list rather than behind a tab: a self-monitoring panel nobody navigates to is one nobody reads, which is §16.2's whole observation.
- [x] **5.4** Run comparison + lineage diff + "why did A win" attribution *(§11.5; after 2.12)* — `ComparisonMatrixView`. A **matrix, not a leaderboard**: a ranked list implies a total order that paired comparisons do not establish, so every cell carries its own mean difference, win/tie/loss record and achieved k, and the reader does the comparing. Every flag is shown above the matrix, and the Wilcoxon p-value is labelled `(descriptive)` **on the surface** rather than only in the type, because a bare p-value beside a verdict reads as the reason for it. Attribution is a decomposition — regime-sliced deltas and gate margins — never a sentence: a narrative explanation of a statistical result is a story fitted to an outcome, and it is most persuasive exactly where it is least justified.
- [x] **5.5** Gate-by-gate result display with trial-count context *(§12.3, §12.2)* — `GET /api/platform/gates/{subject}` returns the newest verdict per gate from `mlops.gate_verdict`, and `GateStackBoard` renders all sixteen rows. The header says `n of 16 recorded` and the board states that an incomplete stack authorises nothing.
- [x] **5.6** Agent action review timeline *(§15; after 2.18)* — `GET /api/platform/timeline` interleaves `audit_event` and `decision` rows in time, because reviewing a session means asking two questions at once — what did it try to do, and what did it choose from — and separately they are two lists nobody correlates. The response counts `prevented` (denied or awaiting approval) separately, which is the number the `pre` records exist to make computable at all.
- [x] **5.7** Preset / guided / expert configuration modes *(§16, ADR-P5-02)* — `ledger::presets`. All three modes are the same schema through the same validator; the difference is presentational. The load-bearing part is that a preset carries `Suggestion`s, **not values**: `Suggestion::value()` returns `None` until a human confirms, `PresetDraft::resolve` refuses an unconfirmed field by name, and `from_preset` refuses a preset that ships an already-confirmed suggestion.
